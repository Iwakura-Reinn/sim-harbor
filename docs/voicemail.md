# 留言

留言默认关闭。关闭时应用只记录来电，不接听、不拒接、不拨号。开启后，所选卡槽由板子自动接听并录音，Harbor 在通话接通后发送一次提示音，板子再把 AMR 上传到局域网里的 SIMHarbor。应用保存录音、尽量关联到来电，并在录音就绪后发送 Bark「有留言」。

这条路径与“只提醒、不接听”互斥。自动接听可能产生通话费用，录音时长以板子固件默认为准。

## 行为

| 状态 | 来电上报 | 板子 | Bark |
| --- | --- | --- | --- |
| 默认关闭 | 记录振铃、接通和结束 | 不下发任何来电控制命令 | 未接仍按原规则提醒 |
| 已开启的卡槽 | 记录上报。602 且 `telConnectedTs` 大于 0 时，Harbor 发送一次 `telstarttts` | 自动接听和录音来自事先下发的来电方式与上传地址。提示音由这一次 TCP 播放 | 录音关联到来电后发送「有留言」，不走未接或“曾来电”提醒 |
| 未选中的卡槽 | 与默认关闭相同 | 保持读回时的原值，接通后不发送 `telstarttts` | 未接规则不变 |

接通后的命令是 `telstarttts`：`p1` 为卡槽数字，`p2` 为系统配置里的提示音，`p3` 为 `1`（只播放一轮；缺省 0 会一直循环），`p5` 为 `0`（播完不挂断，线路留给来电者留言）。不发送 `p4`。同一通来电只发一次，键是卡槽、`telStartTs` 和 `telConnectedTs`。未接通的 601，以及 602 但接通时间为 0，都不发送；发得太早时板子回 `code=200`「No call in progress」。

接受结果是 `type=401`、`subType=26`、`code=0`。不把 `type=402` 当成这条命令的成功，也不等待 687 / 689。失败不自动重发。`p5=1` 不用作留言结束条件。应用仍不发送 `telanswer`、`telstartrecord`、`teldial` 或 `telhangup`。

来电方式为模式 2 时，板子从接听就开始录音。提示音下行和来电者的留言可能进同一段 AMR。

## 网页播放

来电记录里的「播放留言」使用和管理下载相同的凭据，请求 `GET /api/calls/{id}/voicemail`。服务端仍返回原始 AMR，不在镜像里转码。页面在点击后加载 opencore-amr 的 WASM 解码器，得到 PCM，再交给 Web Audio 播放。同一时间只播放一条，离开来电页即停止。「下载 AMR」仍保存原始文件。

板子上传的是 AMR-NB（文件头 `#!AMR`），按 8000 Hz 单声道播放。现代 Chromium 和 Firefox 可以播放。`<audio>` 不能直接播放 AMR。页面的内容安全策略允许编译这段 WASM（`wasm-unsafe-eval`），不放宽脚本 `eval`。解码失败时下载仍然可用。

Safari 不作为这条能力的验收目标。没有 Web Audio 的浏览器会提示无法播放，下载不受影响。

## 开启

1. 确认板子来电策略目前是“不接听”，录音地址为空。需要留言时再继续。
2. 在系统配置填写卡槽、提示音和局域网上传地址。页面可以填入模板；把 `192.168.31.x` 换成这台管理主机的局域网地址，并核对发布端口。
3. 勾选留言确认和保存确认，保存后重启应用。重启前运行中的进程仍按旧配置工作。
4. 打开板子设置，先读取留言参数。读取只走 TCP，不发短信。
5. 确认启用。上传地址用 TCP `setamrurl`。来电方式先试 TCP `slotcim` 模式 2；X32v158 拒绝时，改为从所选卡槽向该卡自己的号码发送 `*#slotNcim#`。启用不再写入 `slottts` 提示音预设，因此短信确认也不再为提示音发指令。其他卡槽不发指令。提示音留在 Harbor，等这张卡接通后再发 `telstarttts`。

上传地址必须是板子能访问的 HTTP，例如 `http://192.168.31.10:18880/api/voicemail/amr/<32位以上十六进制令牌>?slot={{slot}}&start={{telStartTs}}&phone={{phNum|$urlEncode()}}`。要求显式端口、IPv4 私网或本机地址，以及上述路径。公网域名、`nip.io` 和无端口地址不能保存。令牌由浏览器随机生成，不是管理凭据。

板子上传不带管理 Bearer。接口在留言已启用时，同时检查路径令牌和来源 IP 是否落在设备白名单。白名单关闭时拒绝上传。不要把该路径放到未校验来源的公开入口。

## 家庭部署

现有 Compose 默认把网页发布在 `127.0.0.1`。板子访问不到这个地址。留言上传要在宿主把容器 `8080` 发布到局域网 IP 和端口，例如迷你主机 `192.168.31.10:18880`。容器内部仍监听 `8080`。不要为了留言把默认绑定改成 `0.0.0.0`。

在现有项目 `/home/ltj/service/sim-harbor` 上，用覆盖文件增加局域网发布，并保留原来的项目名和数据卷。下面只说明端口形态，地址按现场网卡替换：

```yaml
services:
  sim:
    ports:
      - "192.168.31.10:18880:8080"
      - "192.168.31.10:39090:9000"
```

`setamrurl` 使用宿主局域网 IP 和发布端口 `18880`，不是容器端口 `8080`，也不是 `127.0.0.1`。设备白名单写入板子的来源地址，例如 `192.168.31.175/32`，这样上传的来源就是板子本身。不要把上传再转给会改掉来源地址的反代，除非该反代保留板子地址并且不要求 Bearer。

镜像仍按现有 `sim-harbor` 标签构建。升级前先备份数据库和 `system.private.json`。AMR 文件在数据目录的 `voicemail/`，SQLite ZIP 不包含这些文件；迁移时要单独复制该目录。

## 关闭并恢复

1. 在系统配置取消留言，保存并重启应用。新的来电不再按留言槽抑制未接提醒。
2. 板子上的自动接听不会随应用重启自动撤销。到板子设置重新读取，确认“恢复为不接听并清除提示音和上传地址”。短信通道上，成功表示指令已提交并且上传地址已清空；来电方式往往仍然显示 TCP 未返回。
3. 恢复可以在应用侧留言已经关闭后进行，以便把板子弄回“不接听”。结果未知时先重新读取，不要重复下发。

## 板子命令

厂家 TCP 目录里，录音地址是 `askamrurl`（子类型 56）和 `setamrurl`（子类型 55）。来电方式 `slotcim` 和提示音预设 `slottts` 只有短信指令，没有对应的 TCP 页面。接通后的提示音使用 TCP `telstarttts`，接受回执是 `type=401`、`subType=26`。X32v158 对 TCP `slotcim` 回 401 时，读取仍返回 `askamrurl` 的结果，来电方式标为 TCP 未返回，并且不因此中断查询，也不再接着查询 `slottts`。

确认启用时只写上传地址和来电方式。TCP `slotcim` 被拒绝时，应用从所选卡槽发出短信，收件号码填这张卡自己的号码：

- 来电方式：`*#slot2cim#用户密码#2`（接听并录音）或 `#0`（不接听）。不改响铃次数和最长通话。
- 启用不发送 `*#slotNtts#`。提示音里的 `#`、`@`、`&`、`~` 可以保留，因为接通后走 TCP JSON，不进短信正文。

若板子上还留着以前写入的 `slottts` 预设，接通时预设和 `telstarttts` 会各播一次。恢复会清空这个预设：TCP 能写时用 `slottts` 把文字置空；只能走短信时发送 `*#slot2tts#用户密码#`（密码后不带文字）。需要只保留 Harbor 的一轮提示音时，先恢复再启用。

用户密码在确认时输入，不写入配置，也不进收件箱或 Bark。出厂密码是 `000000`；改过则以板子为准。密码错误时板子 30 分钟内可能只回复一次。密码本身不能含 `#`、`@`、`&`、`~` 或空格。

短信指令会占用这条卡的短信，可能产生费用。读取不会发送。只对系统配置里选中的卡槽发，卡槽 1 为空时不要选它。

X32v158 上，这条控制短信经常没有 type 501 回报（看不到「设置为来电」或「已经取消」）。板子仍然可能已经执行。Harbor 不再把 501 当成成功的唯一条件，因此缺少 501 不会让启用或恢复返回 502。判定是：

- `sendsms` 被板子接受即可。401 code 0 表示正在发送，402 表示命令已处理，502 / 503 是提交或送达类回执。见到 402、502 或 503 后，最多再等大约一秒，以便收下已经在路上的 501。
- 若这一小段时间里什么回执都没有，只要 TCP 写入已经发出，也按已提交完成，并记下诊断。这是为了避免现场再用板子 `/ctrl` 手工补发。
- 若 501 真的到来，正文符合本次指令就记为已确认；正文是密码错误或格式错误则仍然失败。模式 2 的回复可能写成“N 声后自动挂断”，这是固件文案，应用只在本次下发的是模式 2 时把它当成接听并录音。

上传地址仍用 TCP 读回。来电方式在这条固件上读不回来，接口里的模式是本次要下发的目标，不是 TCP 读数。页面会标明短信已提交。接通后是否自动接听，用打电话确认；提示音是否播放，看 Harbor 是否发出 `telstarttts`。

再次点“读取”时，来电方式仍可能显示 TCP 未返回。这表示固件没有 TCP 查询，不表示刚才的短信失败。

## 在 ltj-adl-n 上重新部署并核对卡槽 2

现场目录是 `/home/ltj/service/sim-harbor`，镜像名沿用 `sim-harbor:voicemail-c0a3`。板子 X32v158 在 `192.168.31.175`，SIM 在卡槽 2，卡槽 1 为空。不要改 Compose 默认的 `127.0.0.1` 绑定；局域网发布继续用已有的站点覆盖。

在该目录更新本分支后重建并换上同一镜像标签。下面命令使用仓库里的项目名 `sim` 和文件组合；若这台机器的 `.env` 已经把 `SIM_IMAGE` 设成 `sim-harbor:voicemail-c0a3`，就不要在命令行再写一遍密钥。

```sh
cd /home/ltj/service/sim-harbor
git fetch origin cursor/voicemail-opt-in-c0a3
git checkout cursor/voicemail-opt-in-c0a3
git pull --ff-only origin cursor/voicemail-opt-in-c0a3
docker compose --env-file .env -p sim -f compose.yaml -f deploy/site.private.yaml config --quiet
docker compose --env-file .env -p sim -f compose.yaml -f deploy/site.private.yaml build
docker compose --env-file .env -p sim -f compose.yaml -f deploy/site.private.yaml up -d --no-build --pull never --wait --wait-timeout 60
docker compose --env-file .env -p sim -f compose.yaml -f deploy/site.private.yaml ps
```

系统配置里留言保持开启，卡槽只选 2，提示音和局域网上传地址保持原值。保存后的运行配置要重启应用才生效；网页上的“确认重启应用”即可。然后按这个顺序核对：

1. 板子设置里读取留言参数。应看到上传地址，两个卡槽都是“TCP 未返回”。这次没有短信。心跳和存储查询仍走原来的 TCP。
2. 号码填卡槽 2 的本机号码，可以带 `+` 和国家码。密码填用户密码。若上一版写过提示音预设，先选“确认恢复为不接听并清除提示音和上传地址”，再点“确认下发一次”。
3. 页面应显示短信已提交，而不是 502。没有「已经取消」或「设置为来电」也算完成。恢复会发模式短信和清空预设的短信，并用 `setamrurl` 清空上传地址。
4. 选择“确认启用留言”，再点“确认下发一次”。启用会先自己重新读取，不必再点“读取”；短信通道上读到的空来电方式和空提示音与恢复结果里的 0、空字符串都表示 TCP 未返回，不会因此 409。同样不应因缺少 501 失败。这次不发送 `slottts` 短信。上传地址与系统配置一致，卡槽 1 没有短信。
5. 向卡槽 2 打电话。自动接听后 Harbor 发送一次 `telstarttts`（`p3=1`，`p5=0`），听到提示音一轮，然后留言。Harbor 收到 AMR。这段 AMR 可能同时包含提示音和留言。卡槽 1 不自动接听。同一通电话不应听到第二轮由 Harbor 触发的提示音。
6. 打开 Harbor，在来电记录里找到带留言的那一通，点「播放留言」。Chromium 或 Firefox 应出声。「下载 AMR」仍保存原始文件。
7. 关闭时先在系统配置关掉留言并重启，再在板子设置对卡槽 2 做一次恢复。

## 真机核对

固件目标是绿邮 X3 / X32v158。板子外网保持阻断，上传只走局域网。

1. 留言关闭时打一通测试电话：只有来电记录和未接提醒，TCP 上没有接听、拒接、拨号或录音命令。
2. 读取留言参数不会发送 `sendsms`，也不会改来电方式或提示音。
3. 下发后读回：所选卡槽为接听并录音，上传地址与配置的局域网 URL 一致。启用确认里没有 `slottts` 或提示音短信。响铃次数和最长通话保持固件默认，应用不改这两项。
4. 向该卡槽打电话。板子自动接听后，Harbor 发送一次 `telstarttts`，提示音只播放一轮且不挂断，通话结束后 Harbor 收到 AMR。录音里可能混有这段提示音。
5. 来电记录可以播放或下载 AMR。播放走同一管理凭据，在浏览器里解码 AMR-NB；下载仍是原始文件。Bark 标题含「有留言」，正文不含未接或响铃字样。同一录音重复上传不产生第二条通知。
6. 未开启留言的另一卡槽仍只记录，不自动接听。
7. 按上一节关闭应用开关并恢复板子。再打电话应回到只记录、不接听。
