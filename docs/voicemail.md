# 留言

留言默认关闭。关闭时应用只记录来电，不接听、不拒接、不拨号。开启后，所选卡槽由板子自动接听、播放已保存的提示音并录音，再把 AMR 上传到局域网里的 SIMHarbor。应用保存录音、尽量关联到来电，并在录音就绪后发送 Bark「有留言」。

这条路径与“只提醒、不接听”互斥。自动接听可能产生通话费用，录音时长以板子固件默认为准。

## 行为

| 状态 | 来电上报 | 板子 | Bark |
| --- | --- | --- | --- |
| 默认关闭 | 记录振铃、接通和结束 | 不下发任何来电控制命令 | 未接仍按原规则提醒 |
| 已开启的卡槽 | 仍只记录上报，不在上报后接听或开始录音 | 使用事先下发的自动接听、提示音和上传地址 | 录音关联到来电后发送「有留言」，不走未接或“曾来电”提醒 |
| 未选中的卡槽 | 与默认关闭相同 | 保持读回时的原值 | 未接规则不变 |

应用不会在提示音之后发送 `telstartrecord`，也不会在来电事件上发送 `telanswer`、`teldial` 或 `telhangup`。逐通 TCP 编排录音是后续工作，当前版本不提供。

## 开启

1. 确认板子来电策略目前是“不接听”，录音地址为空。需要留言时再继续。
2. 在系统配置填写卡槽、提示音和局域网上传地址。页面可以填入模板；把 `192.168.31.x` 换成这台管理主机的局域网地址，并核对发布端口。
3. 勾选留言确认和保存确认，保存后重启应用。重启前运行中的进程仍按旧配置工作。
4. 打开板子设置，先读取留言参数。读取只走 TCP，不发短信。
5. 确认启用。上传地址始终用 TCP `setamrurl`。来电方式和提示音先试 TCP；X32v158 会拒绝 `slotcim` / `slottts`，这时改为从所选卡槽向该卡自己的号码发送短信指令，然后用板子回复短信和 `askamrurl` 读回。其他卡槽不发指令。

上传地址必须是板子能访问的 HTTP，例如 `http://192.168.31.10:18880/api/voicemail/amr/<32位以上十六进制令牌>?slot={{slot}}&start={{telStartTs}}&phone={{phNum|$urlEncode()}}`。要求显式端口、IPv4 私网或本机地址，以及上述路径。公网域名、`nip.io` 和无端口地址不能保存。令牌由浏览器随机生成，不是管理凭据。

板子上传不带管理 Bearer。接口在留言已启用时，同时检查路径令牌和来源 IP 是否落在设备白名单。白名单关闭时拒绝上传。不要把该路径放到未校验来源的公开入口。

## 家庭部署

现有 Compose 默认把网页发布在 `127.0.0.1`。板子访问不到这个地址。留言上传要在宿主把容器 `8080` 发布到局域网 IP 和端口，例如迷你主机 `192.168.31.10:18880`。容器内部仍监听 `8080`。不要为了留言把默认绑定改成 `0.0.0.0`。

在现有项目 `/home/ltj/service/sim-harbor` 上，用覆盖文件增加局域网发布，并保留原来的项目名和数据卷。下面只说明端口形态，地址按现场网卡替换：

```yaml
services:
  sim:
    ports:
      - "192.168.31.10:18880:8080"
      - "192.168.31.10:39090:9000"
```

`setamrurl` 使用宿主局域网 IP 和发布端口 `18880`，不是容器端口 `8080`，也不是 `127.0.0.1`。设备白名单写入板子的来源地址，例如 `192.168.31.175/32`，这样上传的来源就是板子本身。不要把上传再转给会改掉来源地址的反代，除非该反代保留板子地址并且不要求 Bearer。

镜像仍按现有 `sim-harbor` 标签构建。升级前先备份数据库和 `system.private.json`。AMR 文件在数据目录的 `voicemail/`，SQLite ZIP 不包含这些文件；迁移时要单独复制该目录。

## 关闭并恢复

1. 在系统配置取消留言，保存并重启应用。新的来电不再按留言槽抑制未接提醒。
2. 板子上的自动接听不会随应用重启自动撤销。到板子设置重新读取，确认“恢复为不接听并清除提示音和上传地址”，读回卡槽模式 0、提示音为空、上传地址为空。
3. 恢复可以在应用侧留言已经关闭后进行，以便把板子弄回“不接听”。结果未知时先重新读取，不要重复下发。

## 板子命令

厂家 TCP 目录里，录音地址是 `askamrurl`（子类型 56）和 `setamrurl`（子类型 55）。来电方式 `slotcim` 和提示音 `slottts` 只有短信指令，没有对应的 TCP 页面。X32v158 对 TCP `slotcim` / `slottts` 回 401 时，读取仍返回 `askamrurl` 的结果，来电方式和提示音标为 TCP 未返回，并且不因此中断查询。

确认写入时，若这两条 TCP 命令被拒绝，应用从所选卡槽发出短信，收件号码填这张卡自己的号码，让指令回到板子：

- 提示音：`*#slot2tts#用户密码#提示音`。清空时密码后不带文字。
- 来电方式：`*#slot2cim#用户密码#2`（接听并录音）或 `#0`（不接听）。不改响铃次数和最长通话。

用户密码在确认时输入，不写入配置，也不进收件箱或 Bark。出厂密码是 `000000`；改过则以板子为准。密码错误时板子 30 分钟内可能只回复一次。提示音里不能有 `#`、`@`、`&`、`~`。

短信指令会占用这条卡的短信，可能产生费用。读取不会发送。只对系统配置里选中的卡槽发，卡槽 1 为空时不要选它。板子回复“已经设置完成”或“已经取消”后，应用才把提示音视为读回；回复正文不包含提示音原文。模式 2 的回复可能写成“N 声后自动挂断”，这是固件文案，应用只在本次下发的是模式 2 时把它当成接听并录音。结果未确认时先重新读取，不要连续重试。

再次点“读取”时，来电方式和提示音仍可能显示 TCP 未返回。这表示固件没有 TCP 查询，不表示上一次短信读回失败。

## 在 ltj-adl-n 上重新部署并核对卡槽 2

现场目录是 `/home/ltj/service/sim-harbor`，镜像名沿用 `sim-harbor:voicemail-c0a3`。板子 X32v158 在 `192.168.31.175`，SIM 在卡槽 2，卡槽 1 为空。不要改 Compose 默认的 `127.0.0.1` 绑定；局域网发布继续用已有的站点覆盖。

在该目录更新本分支后重建并换上同一镜像标签。下面命令使用仓库里的项目名 `sim` 和文件组合；若这台机器的 `.env` 已经把 `SIM_IMAGE` 设成 `sim-harbor:voicemail-c0a3`，就不要在命令行再写一遍密钥。

```sh
cd /home/ltj/service/sim-harbor
git fetch origin cursor/voicemail-opt-in-c0a3
git checkout cursor/voicemail-opt-in-c0a3
git pull --ff-only origin cursor/voicemail-opt-in-c0a3
docker compose --env-file .env -p sim -f compose.yaml -f deploy/site.private.yaml config --quiet
docker compose --env-file .env -p sim -f compose.yaml -f deploy/site.private.yaml build
docker compose --env-file .env -p sim -f compose.yaml -f deploy/site.private.yaml up -d --no-build --pull never --wait --wait-timeout 60
docker compose --env-file .env -p sim -f compose.yaml -f deploy/site.private.yaml ps
```

系统配置里留言保持开启，卡槽只选 2，提示音和局域网上传地址保持原值。保存后的运行配置要重启应用才生效；网页上的“确认重启应用”即可。然后按这个顺序核对：

1. 板子设置里读取留言参数。应看到上传地址，两个卡槽都是“TCP 未返回”。这次没有短信。心跳和存储查询仍走原来的 TCP。
2. 号码填卡槽 2 的本机号码，密码填用户密码。选择“确认启用留言”，再点一次确认。
3. 读回应显示卡槽 2 为接听并录音、提示音已设置，上传地址与系统配置一致。卡槽 1 仍是 TCP 未返回，并且没有给它发短信。
4. 向卡槽 2 打电话：自动接听、播放提示音，Harbor 收到 AMR。卡槽 1 不自动接听。
5. 关闭时先在系统配置关掉留言并重启，再在板子设置对卡槽 2 做一次恢复。恢复同样可能发两条短信，然后用 `setamrurl` 清空上传地址。

## 真机核对

固件目标是绿邮 X3 / X32v158。板子外网保持阻断，上传只走局域网。

1. 留言关闭时打一通测试电话：只有来电记录和未接提醒，TCP 上没有接听、拒接、拨号或录音命令。
2. 读取留言参数不会发送 `sendsms`，也不会改来电方式或提示音。
3. 下发后读回：所选卡槽为接听并录音，提示音与系统配置一致，上传地址与配置的局域网 URL 一致。响铃次数和最长通话保持固件默认，应用不改这两项。
4. 向该卡槽打电话。板子应自动接听并播放提示音，通话结束后 Harbor 收到 AMR。
5. 来电记录可以下载 AMR。Bark 标题含「有留言」，正文不含未接或响铃字样。同一录音重复上传不产生第二条通知。
6. 未开启留言的另一卡槽仍只记录，不自动接听。
7. 按上一节关闭应用开关并恢复板子。再打电话应回到只记录、不接听。
